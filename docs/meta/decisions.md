# decisions.md — 設計判断ログ（ADR形式）

> このファイルには「なぜそう決めたか」を記録する。
> 実装の確定事項はspec.mdへ。変更理由はここに残す。
>
> 対象：自分・開発者・将来の共同研究者
> Claude Codeは変更を加える前にここを確認する
> 変更頻度：判断のたびに追記（削除禁止）

---

## ADRテンプレート

```markdown
## ADR-XXX: [決定の内容]

**日付：** YYYY-MM-DD
**ステータス：** Accepted / Superseded by ADR-YYY / Deprecated

**状況（Context）：**
なぜこの判断が必要だったか

**決定（Decision）：**
何を決めたか

**根拠（Rationale）：**
なぜそれを選んだか。他の選択肢との比較。

**結果（Consequences）：**
この決定による影響・トレードオフ

**代替案（Alternatives Considered）：**
検討したが採用しなかった案とその理由
```

## ADR-001: コサイン類似度を標準類似度として採用する

**日付：** プロジェクト開始時
**ステータス：** Accepted

**状況：**
アンカー座標変換で使用する類似度指標を統一する必要があった。

**決定：**
コサイン類似度（Cosine Similarity）を全システムで標準とする。

**根拠：**
- embeddingの長さに依存しない（正規化済みベクトル同士の内積）
- sentence-transformersのデフォルトと一致する
- 研究コミュニティで最も広く使われており比較しやすい

**結果：**
- ドット積やユークリッド距離を使う場合は必ずコメントに理由を書く
- 実験で他の指標と比較する際は明示的に切り替える

**代替案：**
- ユークリッド距離：embeddingの大きさに依存するため不採用
- ドット積：正規化されていないembeddingに弱いため不採用

## ADR-002: テキスト全文をメモリとして保存しない

**日付：** プロジェクト開始時
**ステータス：** Accepted

**状況：**
長期記憶の実装方針を決める必要があった。

**決定：**
テキスト全文の蓄積を禁止し、bundle構造として保存する。

**根拠：**
- RAGとの差別化（RAGはチャンク保存、意味束AIはbundle保存）
- 長期化による情報肥大化を防ぐ
- 意味圧縮・再構成のコア機能を実現するため

**結果：**
- 全文検索はできない（必要なら別途全文DBを持つ）
- bundleから元のテキストを完全復元できない場合がある
- これはトレードオフとして許容する

## ADR-003: Phase 0ではDBを使わない

**日付：** プロジェクト開始時
**ステータス：** Accepted

**状況：**
Phase 0の技術スタックを決める必要があった。

**決定：**
Phase 0はインメモリ（numpy/dict）のみ。DBは Phase 1から。

**根拠：**
- Phase 0の目的は「概念が機能するか確認する」こと
- DB設定の複雑さをなくして本質に集中する
- PoCが失敗した時のリスクを最小化する

**結果：**
- Phase 0の成果はnotebookで確認する
- Phase 1でDBへ移行する際に、データ構造の変更が必要になる可能性

## ADR-004: 非公開仕様を実装しない

**日付：** プロジェクト開始時
**ステータス：** Accepted

**状況：**
時間ダイナミクス・bundle merge/split の正式仕様は非公開仕様。

**決定：**
これらは hypotheses.md で DEFERRED として管理し、実装しない。

**根拠：**
- 参入障壁として意図的に非公開
- 早期実装すると設計が固まりすぎて将来の仕様確定の余地が減る

**結果：**
- PoCの束の間形式版を使う（simpleな指数移動平均など）
- 将来の仕様確定時に migration が必要

## ADR-005: 文明論・構造心理学・感情推論APIを意味束AI仕様から分離する

**日付：** 2025-05-15
**ステータス：** Accepted

**状況：**
元の統合仕様メモに、意味束AIのコア技術と「斉藤理論群全体の思想的文脈」が混在していた。特に文明論（外部化の連鎖）・構造心理学（心のかたち理論）・感情推論APIとの接続記述が、技術仕様と同じ文書に書かれていた。

研究協力者・実装者・ライセンス先が「どこまでが技術仕様で、どこからが思想なのか」を誤解するリスクがあると判断した。

**決定：**
1. `core/vision.md` から文明論・構造心理学・感情推論APIの記述を削除する
2. これらを `core/theory_map.md` に退避する
3. 技術仕様・論文・ライセンス資料では `theory_map.md` を参照しないルールを設ける
4. 文明論的接続は「思想的・展望的な位置づけ」として明示的にラベルを付ける

**根拠：**
- 意味束AIの技術的主張は文明論・構造心理学が否定されても成立する
- これらを混在させると査読・ライセンス交渉・実装で信頼性が下がる
- 「接続可能な別理論」と「技術仕様の前提」は明確に異なるレイヤー

**結果：**
- 技術文書（vision.md, thesis.md, spec.md, 論文）が理論的に自立する
- 思想的文脈は theory_map.md に集約され、必要な場面で参照できる
- 将来の感情推論APIとの統合も、別プロジェクトとして正式に開始できる

**適用する留保文：**
> 意味束AIは、斉藤理論群全体の中では「構造化された意味を外部化・再利用する技術」として文明論と接続可能である。ただし、この接続は思想的・展望的な位置づけであり、本理論の数理モデルまたは実装仕様の前提ではない。

## ADR-006: 束演算と時間ダイナミクスを非公開仕様として分離管理する

**日付：** 2026-05-19
**ステータス：** Accepted

**状況：**
非公開仕様書v0.2（internal_spec_v0.2.md）に束演算アルゴリズム（§4）と時間ダイナミクス（§5）の詳細が定義されている。これらをdocs/に統合するか、private-specs/に分離管理するかを決定する必要があった。

**決定：**
1. 束演算の**シグネチャと戻り値**のみをspec.md（SB-009）に公開仕様として記載する
2. 束演算の**内部アルゴリズム詳細**はprivate-specs/に保管する
3. 時間ダイナミクス全体をprivate-specs/に保管する
4. private-specs/のREADMEで管理ルールを明文化する

**根拠：**
- 「読めば重要性は100%理解できる・でも再現は0%」という状態を意図的に維持する
- 束演算とTransformerのSelf-Attentionの関係は技術的に類比できる重要な知財
- Lyapunov的安定性を意味空間に適用した時間ダイナミクスは既存研究にない
- これらがライセンス交渉・事業化の核心的な参入障壁になる

**結果：**
- 公開論文・GitHubには効果と結果のみ公開できる
- 共同研究者・ライセンス先にはNDA締結後に詳細を共有できる
- spec.mdは「何を呼べばいいか」を示し、「どう動くか」は非公開を維持できる
